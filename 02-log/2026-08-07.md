세정이 장난감 탭처럼 책도 기록하고 싶어해서 책 탭을 새로 만듦.

### 책 탭 추가
- 상단 탭에 "📚 책" 추가, 장난감 탭과 동일한 구조로 복제 (표/모달/CSS 클래스 재사용)
- 필드: 개월수(복수 선택)·사진 한 장·별점(0.5 단위)·개월수별 후기
- `State.books` 배열 신규 추가, `toys`와 별도로 저장 (섞이지 않음)
- 시드 데이터 없이 빈 배열로 시작
- Supabase `bbf_state.data`에 `books` 필드로 동기화 (스키마 변경 아님, JSON 필드 추가)
- 데스크톱·모바일 브라우저에서 빈 상태/모달 입력/유효성 검사/저장/재편집/삭제 전부 확인

### 3끼 전환 시점 연기 (8/10 → 9/12)
- 원래 8/10부터 3끼("88~115일")로 넘어갈 예정이었으나, 세정 요청으로 9/12까지 2끼 유지
- 8/8~9/11: 매일 동일한 고정 식단(8/8 원래 자동생성 메뉴 기준, 소고기만 20→15g)
  - 1끼: 쌀30·오트밀30·검은콩15·퀴노아15 + 소고기15·두부15·당근15·새송이버섯15·오이15·토마토15·무15 (195g)
  - 2끼: 베이스 동일 + 닭고기10·두부15·당근15·새송이버섯15·오이15·토마토15·무15 (190g)
- 2끼 탭("60~87일"→"60~120일")을 7/13~9/11까지로 확장, 3끼 탭("88~115일"→"121~148일") 시작을 9/12로 이동
- 탭 라벨 문구와 "n일차" 숫자를 실제 날짜 범위에 맞게 재계산
- 7/13~8/7은 기존 자동생성 로직 그대로 유지(변경 없음), 8/8~9/11만 고정 식단으로 교체
- 브라우저에서 8/7(기존값 유지)·8/8~9/11(동일 식단)·9/12(3끼 탭 시작, 빈칸) 확인, 5일짜리 마지막 주(9/7~9/11) 레이아웃도 정상 렌더링 확인

### 장난감·책 개월수: 범위 → 개별 월
- 기존엔 "1~3개월","4~5개월" 같은 범위로 개월수를 묶어서 선택했는데, 세정 요청으로 0~24개월 개별 월 버튼으로 쪼갬
- 색상은 기존 8색 팔레트를 25개월에 순환 적용(m-0~m-7 반복)
- 실제 Supabase에 저장돼 있던 장난감 11개 중 5개(오볼·아기 병풍·까꿍책·치발기·여러 책들)가 범위 라벨을 쓰고 있어서 데이터 마이그레이션 필요 — 세정 확인 후 "범위의 첫 달만 남기고 나머지는 추가하지 않는" 방식으로 결정(예: "1~3개월"→"1개월", "4~5개월"→"4개월", 후기 텍스트는 그대로 유지)
- 기존 6/16~19에 쓰인 `migrateW2Veg`/`migrateRemoveAehobak` 같은 "앱 로드 시 1회만 실행" 패턴을 그대로 따라 `migrateMonthLabels()` 추가 — 세정이 다음에 앱을 열면 자동으로 1회 변환되고 다시 저장됨(내가 직접 운영 DB에 쓰지 않음)
- 실제 Supabase 데이터 구조를 읽기 전용으로 조회해 마이그레이션 대상(11개 중 5개)을 미리 확인 후 진행
- 브라우저에서 25개 월 선택 버튼 레이아웃(데스크톱·모바일), 실제 데이터 형태를 흉내낸 마이그레이션 결과 모두 확인
